# LinkedIn Auto Connector

Расширение для Chrome (Manifest V3), которое само жмёт «Connect» на странице
**Поиск → Люди** в LinkedIn: фильтрует карточки по ключевым словам, отправляет
приглашение без записки, держит человекоподобные паузы и не даёт превысить лимиты.

## Установка

1. `chrome://extensions` → включить **Режим разработчика**.
2. **Загрузить распакованное расширение** → выбрать папку `C:\pets\linkedin-autoconnect`.
3. Открыть LinkedIn, перейти в поиск людей (`linkedin.com/search/results/people/...`)
   и обновить страницу, если вкладка была открыта до установки.

## Как пользоваться

Быстрый путь — из попапа, без единого клика по интерфейсу LinkedIn:

1. Впиши в поле «Кого искать» запрос: `recruiter`, `frontend`, несколько ролей —
   через `OR` (`recruiter OR frontend OR backend`).
2. Жми **Найти и запустить**. Расширение откроет выдачу «Люди» по этому запросу,
   дождётся отрисовки карточек и стартует само.

Переход идёт прямо по адресу `/search/results/people/?keywords=...` — это и есть
уже выбранная вкладка «Люди». Ввод в строку поиска и клик по вкладке не
имитируются: меньше шагов по чужому UI — меньше того, что может сломаться.

Ручной путь, если выдачу хочется отобрать самому (гео, компания, «2-й круг»,
любые фильтры LinkedIn):

1. Настрой поиск в LinkedIn руками.
2. Жми **Старт на вкладке** в попапе или **Старт** на плавающей панели.

Панель показывает статус, счётчики за день и неделю и лог по каждому контакту.
Кнопка **Стоп** прерывает цикл в любой момент, включая паузу между приглашениями.

## Что делает расширение

- Обходит карточки выдачи, догружая их скроллом, и при `autoNextPage` идёт по страницам.
  Кнопка следующей страницы ищется по подписи («Далее ›», «Next», «Следующая
  страница»), а если подписи нет — по номерам: берётся кнопка с числом на единицу
  больше текущей страницы. Переход считается состоявшимся, только когда сменился
  номер страницы или первый профиль в выдаче.
- Фильтрует по тексту карточки (должность, компания, локация — имя из фильтра исключено):
  список ключевых слов = белый список, стоп-слова = чёрный.
- Кликает Connect → в модалке жмёт «Отправить без заметки», либо, в режиме
  «С запиской», сначала «Персонализировать», вписывает текст и жмёт «Отправить».
  Клик идёт полной последовательностью pointer/mouse-событий: Ember-компоненты
  LinkedIn на голый `el.click()` реагируют не всегда.
- Из нескольких открытых `role="dialog"` (оверлей «Сообщения», промо) выбирает
  модалку приглашения по счёту признаков, а чужие диалоги не трогает вовсе.
- Пропускает контакты, для которых LinkedIn требует email.
- Останавливается сам: по дневному лимиту, недельному лимиту, при модалке о лимите
  приглашений от самого LinkedIn и когда подходящие карточки закончились.
- Помнит обработанные профили в рамках сессии — повторно не тыкает.

## Настройки по умолчанию

| Параметр | Значение | Почему так |
| --- | --- | --- |
| Приглашений в день | 20 | Безопасный потолок для аккаунта без Premium |
| Приглашений в неделю | 90 | Ниже порога, на котором LinkedIn режет приглашения |
| Пауза между | 8–22 с | Случайная, чтобы ритм не выглядел машинным |
| Длинный перерыв | каждые 8, по 120 с | Имитация «отвлёкся от ленты» |

Счётчики хранятся в `chrome.storage.local` и сами обнуляются со сменой суток и
ISO-недели (неделя считается с понедельника — как у LinkedIn).

## Риски

Автоматизация действий нарушает пользовательское соглашение LinkedIn. При
агрессивном темпе аккаунт получает ограничение на приглашения, при повторе —
временную блокировку. Дефолтные лимиты подобраны консервативно; поднимать их
стоит только понимая, чем рискуешь.

### Когда LinkedIn поменяет вёрстку

Симптом — в панели «Кнопок «Установить контакт»: 0» и «смотри диагностику в консоли».
В консоли (F12) при каждом старте печатается `[Auto Connector] диагностика страницы`:
сколько интерактивных элементов найдено и образцы их подписей с вердиктом `подходит`.
По этому дампу видно, на что чинить регулярки.

Лечится в `src/content/dom.js`: словарь `RE` (подписи кнопок на en/ru), `cardOf`
(подъём от кнопки к карточке) и `headline`/`nextPageButton` (селекторы).
Остальной код от разметки не зависит.

Проверки детекта живут в `dev/selftest.html` — открой файл в браузере,
он прогонит логику по макету карточек LinkedIn и покажет PASS/FAIL.
После правки регулярок стоит прогнать его первым делом.

### Записка к приглашению

Режим **«С запиской»** в попапе: расширение жмёт «Персонализировать», вписывает
текст и отправляет. Подстановки в шаблоне:

| Плейсхолдер | Значение | Пример |
| --- | --- | --- |
| `{{firstName}}` | первое слово имени | `Zulaika` |
| `{{name}}` | имя целиком | `Zulaika Moldomuratova` |
| `{{headline}}` | подпись из карточки | `IT Recruiter \| Quantitative Research` |

Неизвестные плейсхолдеры вычищаются: человек получит текст без `{{company}}`,
а не с ним. Счётчик в попапе показывает длину **уже подставленной** записки —
`{{firstName}}` занимает 13 символов в шаблоне и длину имени в отправленном
тексте. Потолок 200 символов, лишнее обрезается.

Текст в поле вставляется через нативный сеттер `value` с событием `input`:
Ember держит собственное состояние, и от простого присваивания записка исчезла бы
при отправке.

Персонализированных приглашений у бесплатного аккаунта в месяц немного. Признак
исчерпания — поведенческий, без разбора текстов: LinkedIn либо не показывает
кнопку «Персонализировать», либо не даёт поле ввода, либо держит кнопку отправки
заблокированной. В любом из этих случаев расширение **один раз** пишет в лог
«Записки кончились» и до конца прогона шлёт обычные приглашения — иначе каждая
карточка тратила бы по четыре секунды на заведомо мёртвый путь.

Чаще всего LinkedIn показывает вместо поля ввода Premium-заглушку «У вас
закончились бесплатные персонализированные сообщения» — она распознаётся сразу,
без ожидания таймаута.

Отдельный случай — когда «Персонализировать» уже нажато: модалка переключилась в
режим ввода (или в заглушку), и кнопки «Отправить без заметки» в ней больше нет.
Тогда расширение закрывает окно и заходит **на того же человека** заново — тот, на
ком лимит закончился, не теряется. Страница при этом не перезагружается: после
перезагрузки LinkedIn отбивает первый же запрос.

Кнопка для повторного захода ищется заново по адресу профиля, а не берётся из
сохранённой ссылки: после закрытия модалки карточка перерисовывается, и прежний
узел оказывается оторван от документа — клик по нему уходил бы в пустоту.

При следующем старте попытка повторяется: месяц мог смениться.

### Как работают фильтры

Совпадение по подстроке, регистр не важен, поиск идёт по тексту карточки
(должность, компания, локация) с вырезанным именем человека. Из этого следует:

- `recruiter` **не** поймает «IT Recruitment», «Talent Acquisition» и «рекрутер» —
  для широкого охвата надёжнее `recruit, рекрут, talent, hr, hiring`;
- короткие слова цепляют лишнее: `hr` совпадёт и внутри «Christina».
